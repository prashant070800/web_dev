# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal portfolio for Prashant Singh, served at https://hellops.in via GitHub Pages (custom domain in `CNAME`). The portfolio itself is plain static `index.html`/`style.css`/`script.js` with no front matter, so Jekyll copies it through untouched. The study hub at `/study/` is generated by GitHub Pages' Jekyll from three collections. There is no package manager, linter, or JS build.

## Commands

- Build like GitHub Pages and run the site checks (needs Docker Desktop running): `powershell -ExecutionPolicy Bypass -File tools/build-site.ps1`. Add `-Serve` to preview `_site/` at http://localhost:8000.
- Checks only, against an existing `_site/`: `python tools/check_site.py`. This is the test suite: it asserts that pages exist, links resolve, and repo-only files aren't published. Add expectations to its `REQUIRED_*`/`FORBIDDEN_*` lists.
- Preview just the portfolio without Docker: `python -m http.server 8000`
- Build the resume PDF by hand: `powershell -ExecutionPolicy Bypass -File build-resume.ps1`
- One-time setup on a new machine: `winget install MiKTeX.MiKTeX` and `git config core.hooksPath .githooks`

## Resume pipeline

`resume.tex` is the source. `resume.pdf` is a committed build output, and the site links to it from the nav, the sitemap, and elsewhere. `.githooks/pre-commit` runs `build-resume.ps1` whenever `resume.tex` is staged, then stages the new `resume.pdf`. If the LaTeX build fails, the commit is aborted. Edit `resume.tex` and never hand-edit or swap out `resume.pdf`.

`build-resume.ps1` looks for `pdflatex` on PATH, then falls back to MiKTeX's per-user install path. It builds into `.resume-build/` (gitignored) and only replaces `resume.pdf` when the build succeeds.

`.gitattributes` forces LF line endings for `.githooks/*`, because the hook runs under `sh` and CRLF breaks it.

## Page structure and conventions

- `index.html` is one page. Its `<main>` holds the sections `#experience`, `#projects`, `#skills`, `#education` and `#contact`. When you add or rename a section, update the `.nav-link` anchors in the header too. `script.js` highlights the active nav link by matching `href="#id"` against `main section[id]`.
- **Reveal-on-scroll is progressive enhancement:** `script.js` adds a `js` class to `<html>`, and the CSS hides `.reveal` elements only under `.js .reveal` until the IntersectionObserver adds `.visible`. Give new content blocks the `reveal` class if they should animate in.
- **Videos are click-to-load:** a `.video[data-yt="<id>"]` button (with an optional `data-start` in seconds and an `aria-label` of the form "Play …") is swapped for a youtube-nocookie iframe on click.
- **Design tokens** (the dark palette, Inter / JetBrains Mono fonts, radius and container width) live in `:root` at the top of `style.css`. Reuse them rather than adding hard-coded colors.
- **External assets:** Google Fonts, Font Awesome 6 from cdnjs, and GoatCounter analytics, which is loaded at the end of `<body>`.

## Study hub (Jekyll)

- Content is `_projects/`, `_experience/`, and `_tech/*.md`. The filename is the slug, and the URL is `/study/<collection>/<slug>/`. The front matter schema is in README ("Adding a study page") and the spec in `docs/superpowers/specs/2026-10-12-study-hub-design.md`.
- Cross-links come only from front matter: `tech:` and `experience:` slugs on projects and roles. `_includes/related.html` derives every link, including backlinks on tech pages. `_includes/tag-link.html` renders a slug with no page as a dashed plain chip instead of a dead link. Don't hand-write links between study pages.
- Interview questions live in front matter `questions:` (`q`/`a`) and are rendered by `_layouts/study-item.html` as `<details class="qa">`. Quote every `q:`, and any value containing a colon. `_config.yml` sets `strict_front_matter: true`, so a YAML error fails the build (otherwise Jekyll only warns and publishes the page with no front matter). `tech:` must be an inline list: a bare string makes `contains` substring-match and creates false backlinks, and `check_site.py` rejects it.
- `_layouts/study.html` duplicates the portfolio `<head>` assets, header, nav, and footer. Change both when either changes.
- Never give a `<section>` an `id` on study pages: `script.js` scroll-spies `main section[id]` and would clear the Study nav link's active state.
- `_config.yml` `exclude` keeps repo-only files (`CLAUDE.md`, `README.md`, `docs/`, `tools/`, `resume.tex`, …) off the live site. Add new repo-only files there.
- `sitemap.xml` is a Liquid template that lists every study page automatically.
- `tools/build-site.ps1` sets `PAGES_REPO_NWO` because `jekyll-github-metadata` can't read the repo name from the `github-personal` SSH remote.

## SEO metadata kept in sync

Profile facts are duplicated across the `<head>` of `index.html`: the meta description, the Open Graph and Twitter tags, and the JSON-LD `ProfilePage`/`Person` block (job title, employer, `sameAs` links, `knowsAbout`). When the job title, employer, links or tagline change, update all of them together. Bump `<lastmod>` in `sitemap.xml` when the page or the resume changes meaningfully.
